Contributing

How to generate new screens and contribute to the Mountains design system using Claude Code. You don't need deep technical experience — just follow the steps.

Getting Started

Clone the repo and get it running locally in two steps.

01

Clone the repo

git clone https://github.com/Ridestore-Pirates/mountains-handoff.git cd mountains-handoff
02

Run locally

No install needed — requires Node.js. Serve from the project root so all asset paths resolve correctly.

npx serve . -p 4321

Open http://localhost:4321 — you'll land on the handoff index.

Understanding the System

Before generating anything, get familiar with three things.

01

docs/design.md — the single source of truth

Every color, font size, spacing value, and design rule lives here. Claude reads this file when generating screens. If something isn't in design.md, it shouldn't be in the output.

02

The deployed URL — the visual reference

Keep the live handoff site open alongside Figma when reviewing generated screens. The goal is pixel accuracy against what's deployed.

https://ridestore-pirates.github.io/mountains-handoff/
03

assets/tokens/ — importable token files

If you're building in React, React Native, or SwiftUI, start here — not by copying values manually from Figma. The files are ready to import.

# JavaScript / React import { tokens } from './assets/tokens/tokens.js' # Swift / SwiftUI Color.appPrimary AppTypography.displayXl AppSpacing.space4

Generating a New Screen

Open Claude Code in the project folder and use the prompt below as your starting point. Replace the bracketed part with the screen you're building.

Starting prompt — copy and adapt

Read docs/design.md and review the existing screens in docs/ to understand the design system. Then generate a new screen for [screen name] following the same tokens, grid, components and visual style. Output as a single HTML/CSS file in docs/.

💡
Tips for better output
If the screen has a Figma node ID, include it: "the Figma node is 125:2082".
If it uses a background photo, mention the asset: "use assets/images/bg-top-speed.png".
If Claude invents a color or spacing value not in the system, ask it to correct to the nearest token.
🔁
Iterate in plain English
After Claude generates the file, open it in the browser and compare to Figma. If anything looks off, describe the issue in plain English and ask Claude to fix it. You don't need to edit the code yourself.

Branching Rules

Always work on a dedicated branch. Never commit directly to main.

git checkout -b feature/screen-{name}

New screen → feature/screen-lifetime-card

Token change → feature/tokens-radius-update

Small fix → fix/profile-avatar-radius

⚡
main is always deployable. It's what's live at the public URL. Only merge when a screen is signed off and the checklist below is complete.

Before You Merge

Go through this before opening a pull request. Every item needs a tick.

4px grid Every spacing and sizing value is a multiple of 4px. No 6px padding, no 22px heights, no 46px buttons.
Token names only All colors use CSS variables from assets/css/tokens.css. No invented hex values or raw rgba on dark backgrounds.
Correct viewport The screen renders correctly at 393×852px (iPhone 14 Pro).
Text on dark backgrounds Uses #D5F4FC or #BBE2EC — never white.
No bottom tab bar The app has no bottom navigation. All nav lives in the 3 header icon buttons.
Correct file location and name Saved in docs/ and follows the screen-{name}.html naming pattern.
Screen inventory updated The new screen is listed in the Screens table in docs/design-system.html and index.html.

Flagging for Review

Open a pull request on GitHub and tag Winner for review. Don't merge until it's signed off.

01

Push your branch

git push -u origin feature/screen-{name}
02

Open a pull request

Go to the repo on GitHub and open a PR from your branch into main. A good PR description includes:

→ Which Figma node or screen this corresponds to

→ A screenshot or browser preview of the output

→ Any known issues or decisions you made during generation

03

Tag Winner for review

If something doesn't match Figma exactly, note it in the PR — that's useful signal for improving the prompt or the design.md source. Don't try to hide it.
